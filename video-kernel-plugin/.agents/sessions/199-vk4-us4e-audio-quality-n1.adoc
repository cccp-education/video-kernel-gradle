== Mission

Promouvoir au noyau N1 les deux primitives audio **pures** qui ont maintenant
**deux consommateurs réels** :

* `capsule` — `verifyCapsuleVoice` (take muet, S-209) ;
* `hyperframes` — `generateHyperframesNarration` (narration muette).

Le noyau porte la **décision** (`AudioSilenceDetector`) et la **normalisation**
(`RmsEnvelope`) ; chaque moteur garde son décodage ffmpeg en N2.

== Constat (audit)

* `capsule.voice.AudioSilenceDetector`, `SilenceAnalysis`, `RmsEnvelope` étaient
  des copies locales (S-209).
* `hyperframes` n'avait aucune vérification de silence sur ses narrations
  `narration-<n>.wav` — un TTS NoOp/cassé restait invisible.
* La doctrine « factoriser à 2 » (amendement S-195) est satisfaite : deux
  moteurs, deux usages réels.
* Le noyau interdit `ProcessBuilder` (`video.ci.KernelBoundaryAudit`) : les
  décodeurs restent N2.

== Décisions

. **Package `video.kernel.audio`** : `RmsEnvelope`, `AudioSilenceDetector`,
   `SilenceAnalysis`.
. **Version `0.5.0 → 0.6.0`** (additif), manifeste d'API **+3 types**.
. **Capsule adopte directement** : les copies locales sont supprimées, les
   imports basculent sur `video.kernel.audio.*`.
. **Hyperframes devient 2ᵉ consommateur** : `AudioEnvelopeProbe` (N2 ffmpeg) +
   `NarrationSilenceCheck` (pur) + warning dans `generateHyperframesNarration`.
. **DAG** : `video-kernel 0.6.0` → MEMPHIS `0.0.112` → capsule + hyperframes.
. **Aucun changement de comportement** pour les consommateurs existants : le
   détecteur est identique, seul le package change.
