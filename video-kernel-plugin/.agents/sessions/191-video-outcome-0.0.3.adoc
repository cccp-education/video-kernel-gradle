== Objectif

Combler le **gap confirmé par le spike hyperframes** (S-016) : `VideoRenderResult`
ne portait que `produced: File?`, donc un orchestrateur ne pouvait pas lire les
vidéos des deux moteurs uniformément. Ajouter un **descripteur d'issue neutre**.

== Changements (0.0.3)

* **`VideoOutcome`** (nouveau, `capsule.kernel`) :
  `durationSeconds`, `width`, `height`, `sizeBytes`, `codec?` — champs totaux à
  défauts neutres (`0`/`null` = inconnu).
* **`VideoRenderResult`** : `{ produced, outcome: VideoOutcome?, failedUnits }`.
* Alimenté par **les deux moteurs** :
  * capsule (reveal.js) : durée via `MediaProbeUtil` (ffprobe), dims du viewport de
    capture, `sizeBytes` du fichier, codec par conteneur (`mp4→h264`, `webm→vp8`).
  * hyperframes : `sizeBytes` du fichier, dims/codec de la config ; durée `0.0`
    (inconnue côté CLI, à lire du parse context N3 si besoin).
