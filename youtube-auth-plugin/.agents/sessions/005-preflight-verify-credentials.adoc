== Mission

Répondre au premier déploiement YouTube réel (transverse video-kernel /
hyperframes / capsule) : rendre le chemin vérifiable **avant** tout upload.

== Constat déclencheur

Les `youtube.yaml` des consommateurs portent `clientId`, `clientSecret`,
`channelId`, mais un **`refreshToken` vide** : `canUpload=false` et le refresh
renvoie `400 invalid_request: Missing required parameter: refresh_token`. Aucun
moyen de savoir, avant un upload, si le token pointe la bonne chaîne.

== Livré (US-5)

* Domaine pur `video.auth` :
  * `YouTubeChannel` + `YouTubeChannelProbe` — extraction sans dépendance de
    l'`id` (`UC…`) et du `title` d'une réponse `channels.list` ;
  * `YouTubeChannelCheck` — verdict pur (non configuré / concordant /
    discordant) avec message actionnable sans secret ;
  * `YouTubeRefreshRequest` — forme exacte du grant `refresh_token`.
* `CredentialsFileRewriter.channelId` (lecture du canal configuré).
* `GoogleTokenExchanger.refresh(...)` — grant refresh-token (même endpoint).
* Seam `JsonGetTransport` + `JdkJsonGetTransport` (JDK HttpClient, zéro dép.).
* Tâche `verifyYouTubeCredentials` (groupe `deploy`) : lit le fichier,
  vérifie la complétude, rafraîchit le token, appelle
  `channels.list?mine=true`, compare à la chaîne configurée, écrit
  `build/youtube-auth/verify.json`. **Zéro upload, zéro secret journalisé.**
  `verifyStrict` (défaut `true`) → garde dure ; `false` → avertissement.
* DSL : `youtubeAuth.verifyChannelId`, `youtubeAuth.verifyStrict`,
  `youtubeAuth.channelTransport` (seam test-injectable).
