== Déclencheur — mauvais compte Google dans le consentement

Le flux `obtainYouTubeRefreshToken` ouvrait l'URL de consentement dans le
**navigateur par défaut** (`Desktop.browse`). Sur le poste du pilote, le profil
Chrome par défaut est déjà connecté à un compte Google qui n'est pas celui de la
chaîne YouTube cible : Google répondait au consentement avec ce compte, et le
refresh token produit pointait la mauvaise chaîne.

Le consentement n'est pas un simple GET : c'est une **session navigateur**. Il
faut donc une session **sans cookie** qui laisse l'utilisateur choisir le compte
initialement, au lieu d'hériter de la session ouverte.

'''
== Correctif (DDD/TDD)

Nouveau domaine/adapter dans `video.auth.oauth` :

* `BrowserLaunchOptions` — binaire explicite, répertoire de profil, mode
  `freshProfile`, arguments supplémentaires.
* `ChromiumLaunchCommand` *(pur)* — construit l'argv
  `chromium --user-data-dir=<profil> --no-first-run --no-default-browser-check
  --disable-search-engine-choice-screen --new-window <url>`.
* `BrowserExecutableResolver` *(pur à probe injectée)* — auto-détection
  Chrome/Chromium/Brave/Edge/Vivaldi (Linux/macOS/Windows), un binaire explicite
  restant prioritaire.
* `BrowserLauncher` — lance Chromium sur un profil **neuf** à chaque exécution
  (`session-<epoch>-<uuid>`), donc un pot à cookies vide ; repli sur le
  navigateur par défaut seulement si aucun Chromium n'est présent (avec
  avertissement). Le profil temporaire est supprimé après succès.
* `YouTubeAuthExtension` — `browserExecutable`, `browserProfileDir`,
  `freshBrowserProfile` (défaut `true`).
* `ObtainYouTubeRefreshTokenTask` — câblage + messages (profil isolé vs repli +
  consigne « connectez-vous avec le compte de la chaîne cible »).

Aucun changement de comportement hors navigateur : le flux loopback, l'échange de
token et la réécriture du fichier sont inchangés.

'''
